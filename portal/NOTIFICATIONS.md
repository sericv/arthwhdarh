جمعية إرث وحضارة بالقريات · البوابة الداخلية

## ١. الحالة الحالية للإشعارات

منظومة من **ثلاث طبقات** تضمن وصول الإشعار في كل الحالات:

| الطبقة | تعمل عندما | التقنية |
|--------|-----------|---------|
| **١) Push عبر الخادم** | البوابة **مغلقة كلياً** / تبويب مغلق / تصفّح موقع آخر / تطبيق PWA مغلق | Cloud Function → FCM → `firebase-sw.js` |
| **٢) إشعار متصفح محلي** | البوابة في الخلفية والتبويب مفتوح | `watchNotifications` + `Notification API` |
| **٣) داخل التطبيق** | البوابة مفتوحة وظاهرة | Firestore لحظي (`onSnapshot`) |

### متى تصل الإشعارات الآن؟
- ✅ أغلق الموظف صفحة البوابة
- ✅ أغلق كل تبويبات البوابة
- ✅ يتصفّح موقعاً آخر
- ✅ خرج من تطبيق البوابة
- ✅ ثبّت البوابة كـ PWA (أندرويد/سطح المكتب)
- ✅ أجهزة أندرويد (دفع كامل)
- ⚠️ آيفون: يتطلب **تثبيت البوابة كـ PWA** أولاً (قيد نظام iOS — مفصّل أدناه)

## ٢. المشاكل المكتشفة · السبب الجذري · الإصلاح

| # | المشكلة | السبب الجذري | الإصلاح المطبّق |
|---|---------|-------------|----------------|
| 1 | لا تصل إشعارات بعد إغلاق البوابة | لا توجد طبقة خادمية ترسل دفعاً عبر FCM | أُضيفت **Cloud Function** `sendPushOnNotification` تستمع لـ `portal_notifications` وترسل دفعاً |
| 2 | جهاز واحد فقط لكل مستخدم | الرمز يُخزَّن في حقل مفرد `fcmToken` يُكتب فوقه | مجموعة جديدة **`portal_fcm_tokens`** (مستند لكل رمز) تدعم أجهزة/متصفحات متعددة |
| 3 | الرموز الباطلة تتراكم | لا تنظيف | الـ Cloud Function تحذف الرموز غير الصالحة تلقائياً بعد كل إرسال + المستخدم يحذف أجهزته يدوياً |
| 4 | النقر على الإشعار لا ينقل لوجهته | الـ SW يفتح البوابة فقط دون سياق | `notificationclick` يحمل `link` + `refId`، يركّز البوابة ويرسل `postMessage` لها للتنقّل العميق (`#tasks:ID`) |
| 5 | ٥ فئات إشعارات فقط | تعريف ناقص | وُسّعت إلى **٨ فئات**: مهمة جديدة، تحديث مهمة، اكتمال مهمة، ملف جديد، اعتماد، رفض/تعديل، تعليق، تنبيه نظام |
| 6 | لا تحكّم بالفئات | غير موجود | **تفضيلات الإشعارات** (٥ مجموعات) في الإعدادات، تُحفظ على المستخدم وتُحترم في الواجهة والخادم |
| 7 | مركز إشعارات بسيط | لا بحث/فلترة | **مركز إشعارات** كامل: بحث + فلترة بالفئة/الحالة + عدّادات + سجلّ |
| 8 | لا دعم PWA | لا manifest | أُضيف **`manifest.webmanifest`** + وسوم iOS + `theme-color` + أيقونات |
| 9 | الرمز يبقى بعد الخروج | لا إلغاء تسجيل | `doLogout` يحذف رمز الجهاز الحالي |
| 10 | لا تتبّع للأجهزة | غير موجود | بصمة جهاز (متصفح/نظام/PWA) + `lastSeen` + قائمة أجهزة قابلة للإدارة |

## ٣. التحقق من المتطلبات (تدقيق)

| المتطلّب | الحالة | التفصيل |
|---------|--------|---------|
| تسجيل Service Worker | ✅ | مسار نسبي `firebase-sw.js`، `skipWaiting`+`clients.claim` |
| توليد الرمز | ✅ | `getToken` بمفتاح VAPID العام بعد `isSupported()` |
| تخزين الرمز | ✅ | `portal_fcm_tokens/{token}` متعدد الأجهزة |
| تحديث الرمز | ✅ | `lastSeen` عند كل دخول + إعادة الحفظ عند تغيّره |
| إشعارات المقدمة | ✅ | `onMessage` + toast |
| إشعارات الخلفية | ✅ | `onBackgroundMessage` في الـ SW |
| النقر والتنقّل | ✅ | جسر `postMessage` + هاش عميق |
| فئات (٨) | ✅ | `NOTIF_TYPE` |
| تفضيلات | ✅ | `notifPrefs` على المستخدم |
| أجهزة متعددة | ✅ | مجموعة الرموز |
| تنظيف الباطل | ✅ | تلقائي في الـ Function |
| مركز إشعارات | ✅ | بحث/فلترة/سجلّ |
| PWA | ✅ | manifest + iOS meta |
| تسجيل تشخيصي | ✅ | `[FCM]` `[SW]` `[Firestore]` `[Storage]` `[Portal]` |

## ٤. النشر (الخطوات المطلوبة لتفعيل الدفع الكامل)

```bash
# 1) الفهارس + القواعد
firebase deploy --only firestore:rules,firestore:indexes,storage:rules

# 2) الطبقة الخادمية للدفع (مطلوبة لوصول الإشعار بعد إغلاق البوابة)
cd portal/functions
npm install
firebase deploy --only functions
```

> بدون الـ Cloud Function تعمل الطبقتان ٢ و٣ (داخل التطبيق + خلفية التبويب)
> لكن **لا يصل الدفع بعد إغلاق البوابة كلياً**. الـ Function هي ما يفعّل ذلك.

## ٥. القيود المتبقية

| القيد | السبب | الحل |
|-------|------|------|
| **آيفون يتطلب تثبيت PWA** | iOS (16.4+) لا يدعم Web Push إلا بعد «إضافة إلى الشاشة الرئيسية» | المستخدم: Safari → مشاركة → إضافة إلى الشاشة الرئيسية، ثم يفتح البوابة من الأيقونة ويفعّل الإشعارات |
| **يتطلب HTTPS** | FCM وSW لا يعملان على `http://` (عدا localhost) | نشر الموقع على HTTPS (مفعّل تلقائياً على GitHub Pages/Firebase Hosting) |
| **الدفع يحتاج Cloud Function** | لا يمكن إرسال دفع عبر-أجهزة من الواجهة بالمفتاح العام وحده | نشر `functions/` (خطوة لمرة واحدة) |
| **بطاريات أندرويد العدوانية** | بعض المصنّعين يقيّدون الخلفية | المستخدم يستثني التطبيق من تحسين البطارية |

## ٦. الأمان
- المفتاح الخاص (Private VAPID) **لا يوجد في أي ملف واجهة ولا في الـ Functions** —
  Admin SDK يستخدم صلاحيات المشروع. الواجهة تستخدم المفتاح العام فقط.
- قواعد `portal_fcm_tokens` تمنع أي مستخدم من قراءة/حذف رموز غيره.
