# البوابة الداخلية — جمعية إرث وحضارة بالقريات

بوابة موظفين داخلية متكاملة مدمجة في موقع الجمعية، بهوية تراثية فاخرة.
مبنية على **Firebase** (Authentication · Firestore · Storage · Cloud Messaging).

---

## ١. هيكل المشروع

```
portal/
├── index.html              # الصفحة الرئيسية (SPA) — الدخول + التطبيق
├── manifest.webmanifest    # بيان PWA (تثبيت + إشعارات الجوال)
├── seed.html               # أداة إنشاء حسابات الموظفين (تُستخدم مرة ثم تُحذف)
├── firebase-sw.js          # Service Worker — إشعارات الخلفية + النقر العميق
├── config.js               # الإعدادات: Firebase، الأدوار، الإدارات، الإشعارات
├── services.js             # طبقة الخدمات: Auth / Firestore / Storage / FCM
├── app.js                  # منطق الواجهة: التنقّل، الملفات، المهام، الإشعارات…
├── portal.css              # الأنماط الكاملة (هوية تراثية)
├── firestore.rules         # قواعد أمان Firestore
├── firestore.indexes.json  # الفهارس المركّبة
├── storage.rules           # قواعد أمان Storage
├── functions/              # Cloud Functions — إرسال دفع FCM عبر الخادم
│   ├── index.js
│   └── package.json
├── .env.example            # نموذج متغيرات البيئة
├── NOTIFICATIONS.md        # تقرير تشخيص منظومة الإشعارات
└── README.md               # هذا الملف
```

> ملاحظة معمارية: نظراً لأن الموقع ثابت (Static) بلا أدوات بناء، نُظّم الكود في
> طبقات منطقية — `config` (إعدادات) · `services` (تكامل Firebase) · `app` (واجهة).
> كل منطقة وظيفية (الملفات/المهام/الإشعارات/سجل النشاط) معزولة داخل `app.js`
> بدوال مستقلة قابلة للصيانة.

## ٢. الإعداد السريع

### أ. تفعيل خدمات Firebase
من **Firebase Console** للمشروع `arthwhdarh-782ec`:
1. **Authentication** → فعّل تسجيل الدخول بـ Email/Password.
2. **Firestore Database** → أنشئ قاعدة بيانات (Production mode).
3. **Storage** → فعّل التخزين.
4. **Cloud Messaging** → موجود تلقائياً (مفتاح VAPID العام مُعدّ).

### ب. نشر قواعد الأمان والفهارس
- Firestore → Rules → الصق محتوى `firestore.rules` → **Publish**.
- Storage → Rules → الصق محتوى `storage.rules` → **Publish**.
- **الفهارس المركّبة** (`firestore.indexes.json`): يحتاجها استعلاما الملفات والإشعارات.
  انشرها بـ `firebase deploy --only firestore:indexes`، أو ببساطة افتح رابط
  الإنشاء الذي يظهر في تحذير وحدة التحكم/الكونسول أول مرة.
  > ملاحظة: البوابة **تعمل فوراً بدون الفهارس** عبر ترتيب احتياطي في جهة
  > العميل؛ لكن إنشاءها يحسّن الأداء على البيانات الكبيرة.

### إشعارات المتصفح (FCM)
- يُكتشف دعم المتصفح تلقائياً عبر `isSupported()`.
- المتصفحات المدعومة: إشعارات دفع كاملة (تعمل والتبويب مغلق).
- المتصفحات غير المدعومة (Safari قديم، وضع خاص، بلا HTTPS): سقوط تلقائي
  إلى **إشعارات المتصفح القياسية** دون أي رسائل خطأ.
- التشخيص الكامل في الكونسول تحت الوسم `[FCM]`.
- يتطلب FCM تقديم الموقع عبر **HTTPS** (أو `localhost` للتطوير).

### ج. إنشاء الموظفين
افتح `portal/seed.html` في المتصفح وأنشئ الحسابات.
**أنشئ أول حساب بدور `executive`** (الإدارة التنفيذية) ليتمكن من إدارة كل شيء.
بعد إنشاء الحسابات، احذف `seed.html` أو امنع الوصول إليه.

### د. الدخول
افتح `portal/index.html` وسجّل الدخول.

## ٣. الأدوار والصلاحيات

| الدور | الرمز | الوصول |
|------|------|--------|
| الإدارة التنفيذية | `executive` | **كل شيء** + إنشاء المهام + اعتماد الملفات + إدارة الموظفين |
| الإدارة المالية | `finance` | ملفات المالية (مصروفات/ميزانيات/فواتير) + مهامها |
| إدارة المشاريع | `projects` | ملفات المشاريع (تقارير/برامج/عقود) + مهامها |
| الإعلام والعلاقات | `media` | ملفات الإعلام (صور/فيديو/تصاميم) + مهامها |

## ٤. هيكل البيانات (Firestore)

```
portal_users/{uid}          { name, email, role, fcmToken?, createdAt }
portal_files/{id}           { name, url, storagePath, size, mime, department,
                              category, status, note, comments[], uploadedBy,
                              uploaderName, createdAt, updatedAt }
portal_tasks/{id}           { title, description, priority, status, dueDate,
                              assignType, assignTo, assignLabel, createdBy,
                              creatorName, createdAt, updatedAt }
portal_notifications/{id}   { userId, type, title, body, link, read, createdAt }
portal_activity/{id}        { type, actorId, actorName, resource, detail, createdAt }
```

- `userId` في الإشعارات يقبل `uid` مباشرة أو `dept:{role}` لبثّ إشعار لإدارة كاملة.

## ٥. الميزات المنجزة

- ✅ **مصادقة آمنة** عبر Firebase Auth بأربعة أدوار.
- ✅ **لوحة معلومات** ببطاقات إحصائية + آخر النشاطات + المهام + الملفات.
- ✅ **إدارة ملفات** لكل إدارة وتصنيفاتها: رفع · تنزيل · بحث · تصفية · معاينة · حالة.
- ✅ **سير اعتماد الملفات**: مسودة → قيد المراجعة → معتمد → يحتاج تعديل (مع تعليقات).
- ✅ **إدارة مهام** بلوحة حالات (معلقة/قيد التنفيذ/مراجعة/مكتملة) + أولويات + إسناد لموظف أو إدارة.
- ✅ **إشعارات** لحظية داخل التطبيق + إشعارات المتصفح (FCM) عند: مهمة جديدة، ملف جديد، اعتماد، طلب تعديل، اكتمال مهمة.
- ✅ **سجل نشاط** شامل بالطوابع الزمنية وبيانات المستخدم.
- ✅ **تصميم تراثي فاخر** متجاوب بالكامل على الجوال والكمبيوتر.

## ٦. الأمان

- **لا تُخزّن أسرار في كود الواجهة.** مفاتيح Firebase العامة آمنة بطبيعتها
  وتُحمى عبر قواعد Firestore/Storage.
- **مفتاح VAPID الخاص** (Private Key) لا يوجد في أي ملف هنا — يُستخدم فقط
  في الخادم لإرسال إشعارات FCM (عبر Cloud Functions مثلاً).
- راجع `.env.example` لقائمة المتغيرات.

## ٧. إشعارات الخادم (اختياري — للدفع التلقائي)

الإشعارات داخل التطبيق تعمل فوراً عبر Firestore.
لإرسال إشعارات **Push** للأجهزة المغلقة، أنشئ Cloud Function تستمع لإضافة
مستند في `portal_notifications` وترسل عبر FCM باستخدام **المفتاح الخاص**
المحفوظ في بيئة الخادم (وليس هنا).
